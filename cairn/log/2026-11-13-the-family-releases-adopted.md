# The family releases of 2026-11-13 adopted

Himalaya builds on the io-* releases published on 2026-11-13, all from crates.io: io-imap 0.9.0, io-smtp 0.8.0 (from 0.6.0, the 0.7 line skipped), io-jmap 0.8.0, io-gmail 0.7.0, io-msgraph 0.8.0, io-managesieve 0.3.0, io-maildir 0.4.0, io-mbox 0.2.0, io-sasl 0.2.0, io-http 0.7.0 through the three HTTP crates, and io-oauth 0.6.0 for the live suites. The git pins of io-gmail, io-imap, io-jmap, io-maildir, io-msgraph and io-mbox left `[patch.crates-io]`, each pinned commit being an ancestor of its release tag; the pins of pimalaya-cli and mime-rs stay. `cargo tree -i` shows one io-http (0.7.0), one io-sasl (0.2.0) and one io-oauth (0.6.0). pimalaya-stream 0.3.1 keeps io-proxy 0.1.1, io-proxy 0.2.0 waiting on a pimalaya-stream release.

- SCRAM (family audit of 2026-11-13, SASL-S1): `cargo tree -e features -i io-imap` and `-i io-smtp` listed `client`, `rustls-ring` and `url`, no `scram`, while io-managesieve had it. The configuration takes `scram-sha-256` for the three, so an IMAP or an SMTP account naming it failed as an unsupported mechanism. The `imap` feature enables `io-imap/scram` and `smtp` enables `io-smtp/scram`. The clients still draw the nonce a configuration leaves empty.
- SMTP envelope (SMTP-S1): src/smtp/backend.rs and src/smtp/send.rs cut an address at its last `@` and built the mailbox from the two halves, whose fields io-smtp 0.8 made private. Both parse through `SmtpMailbox::try_from`, the error naming the address with its control characters escaped. `smtp send` keeps its flags as strings checked by the value parsers, so a refused address still exits 2, and builds the paths when it runs; both run `SmtpMessageSend` through the client's `run`, which takes borrowed paths, so no dependency on bounded-static was added. `SmtpParameter::envid` returns a result, propagated. src/email/submission.rs, where every envelope read from headers is derived, the pimdir queue's included, refuses an address holding a control character: `an_address_holding_a_control_character_is_refused` failed before the fix on `To: b<BEL>c@y.org`, which gave the recipient `b\u{7}c@y.org`. The two parser tests of src/smtp could not be run on the old code, which no longer compiles against io-smtp 0.8.
- IMAP: the fourteen data commands return an `ImapOutput`. `output_data` (src/imap/utils.rs) takes its data at every call site, warning of the lines skipped for not decoding, with their count and the command, and of each `ALERT` text. `get_message` fails saying the answer does not decode when its FETCH held such a line and no message, where it would have said `message-not-found`. A `SELECT` whose output a command drops is not read for alerts. `ImapCopyUid` is a struct of ranges: `imap copy` and `imap move` list its pairs, each source beside its destination, up to a million; `copy_messages` and `move_messages` read the source UIDs of a `COPYUID` counting no more than the UIDs asked, and fall back on the `UID SEARCH` otherwise. The `NO` and `BAD` refusals read the text of an `ImapStatusError`.
- mbox: `MboxEntryUpdate` given an index refuses, before writing, a message the file no longer holds where the index says. `update` (src/mbox/backend.rs) now plans its edits from the index through a closure, and on `Stale` rebuilds the index, plans again and passes no index, so the file is scanned whole under the lock; `store_flags`, `edit_flags` and `delete_messages` go through it. `a_write_rebuilds_a_stale_index_once` failed without the retry with `Mbox message update failed: message baqfy5rb6jadmrol moved, rebuild the index and retry`. A move is left alone: its copy reads each message first, where a stale index already failed before this change, and a retry of the whole move after a removal failing as stale would copy twice. `MboxFlag::Keyword` holds an `MboxKeyword`, so `flag_to_mbox` returns a result and a keyword `X-Keywords` would not give back is refused (`a_keyword_the_file_would_not_give_back_is_refused`). `MboxStore::resolve` returns no path for a name it refuses: `resolve_name` (src/mbox/client.rs) turns it into io-mbox's `InvalidName`, on the reads too.
- JMAP: `method_responses` holds raw JSON, which `jmap query` parses back into values, its output and schema unchanged. `jmap mailbox update` wraps its parent and role for the `Option<Option<T>>` fields. `EmailSubmission/set` now returns the answer to the implicit `Email/set` (JMAP-04): a send warns that the message stays a draft when that call fails or leaves the email in `notUpdated`.
- Gmail: the enums gained `Unknown`, printed as `unknown` by the text forms. Graph: `user_path` returns a result, `message_get` takes a `$select` and an `$expand` (none passed), the recipients are a `MsgraphField`. ManageSieve, IMAP and SMTP session options take their SCRAM bounds from the defaults.

Tests changed for a type that moved, none for a behaviour: `the_text_form_says_whether_a_copyuid_came_back` (src/imap/message/copy.rs) builds an `ImapCopyUid` of ranges; `a_tagged_no_reads_as_a_refusal` and `a_refused_lsub_reads_as_a_refusal` (src/imap/outcome.rs) build an `ImapStatusError`; `mbox_flags_round_trip_through_the_shared_flag` builds `MboxKeyword`s; the `entry` helper of src/maildir/backend.rs builds its `MaildirFullEntry` from a `MaildirEntry`. Added: seven unit tests (two in src/imap/message/copy.rs, two in src/mbox/backend.rs, one in src/smtp/backend.rs, src/smtp/send.rs and src/email/submission.rs each).

Verified: `cargo fmt --check`; `cargo clippy --locked --all-targets -- -D warnings` over the fourteen feature sets of .github/workflows/tests.yml; `cargo test --locked --all-features`, 651 passed and 23 ignored, of which 567 passed and 1 ignored in the binary (560 before); `cargo test --locked --no-default-features --features rustls-ring,maildir`, 319 passed. The suites of tests/google.rs, tests/microsoft.rs and tests/fastmail.rs compiled and were not run. No account and no live store was reached.

Spec: backends ("An IMAP answer missing lines says so" added; the IMAP copy and move counts, the mbox backend, its flags and its cache, the sending transport and the JMAP send amended), commands (the `COPYUID` of `imap copy` and `imap move`), packaging (the `scram` features).

Left:

- A Gmail resource holding an `Unknown` value prints in text and fails under `--json`, io-gmail refusing to serialise the variant: the JSON form of such a value is to be decided.
- The million pairs `imap copy` and `imap move` list at most is Himalaya's own bound, not a setting.
- The JMAP upload and download URLs are still filled by hand from the session templates, with an empty account id when the session names none, where io-jmap offers `account_for`, `resolve_upload_url` and `resolve_download_url`.
- The SCRAM iteration bounds, `skip_refused_recipients`, a JMAP mailbox moved to the top level and a Graph `$select` are not exposed.
