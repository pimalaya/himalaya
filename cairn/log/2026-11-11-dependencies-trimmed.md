# Dependencies trimmed

Himalaya's dependencies take Ortie's shape (ortie 2026-11-09-dependencies-trimmed, 2026-11-09-deny-warnings-cleared).

- Cargo.toml: every dependency, build and dev ones included, takes `default-features = false` and names its features, each checked against the item it gates rather than by compiling alone, feature unification hiding a missing one: anyhow `std`, schemars `chrono04`, `derive` and `std`, serde `derive` and `std`, serde_json `std`, mime_guess `rev-mappings` (`get_mime_extensions_str`), mime-rs `base64`, `encoding` and `parser`; ariadne, dirs, gethostname, humansize, log, percent-encoding, secrecy, sha2 (its `alloc` and `oid` dropped, const-oid leaving) and url (neither `serde` nor `std`: no Himalaya type holds a `Url`, and `ParseError` is a `core::error::Error`) take none. tempfile loses `getrandom`. open, convert_case and uds_windows, which nothing used, are gone; toml moves to the dev-dependencies, the tests being its only user, and toml_writer leaves the tree. pimalaya-cli's `prompt` moves under the `pimdir` feature, `pimdir queue cancel` being its only user, so a build without pimdir leaves inquire and crossterm out.
- base64 0.23 gives way to base64-codec 0.1 in Himalaya's code: src/shared/base64.rs holds `encode` (standard, padded) behind the `imap fetch` body, the JMAP `Basic` header and the `attachment download --stdout` data, and `decode_strict` behind the MCP `attach-data`, which takes a `data` only when it is the very encoding of the bytes it decodes to, padding at most canonical. `decode_strict` agreed with the former `GeneralPurpose` decoder (standard alphabet, `DecodePaddingMode::Indifferent`) on all 287,130,469 inputs tried, on the portable backend and on the AVX-512 VBMI one this machine detects: every string of up to 7 bytes over `AQgwaz09+/=-_`, space, LF and `*`, and 200,000 encodings of random bytes, each also unpadded, over-padded and with one byte changed. A refused `data` keeps `attachment-invalid`, its message naming the form taken (`standard alphabet, padding optional, no whitespace`) rather than the offset. `body_prints_as_standard_padded_base64` (src/imap/fetch.rs), `basic_auth_is_standard_padded_base64` (src/jmap/client.rs), `data_is_the_standard_alphabet_padding_optional` (src/mcp.rs) and the literal `data` of `stdout_bytes_are_the_decoded_part` (src/shared/attachment/download.rs) passed on the base64 crate before the switch. tests/mcp.rs encodes and decodes through base64-codec, asserting the server's base64 is the canonical padded form. base64 0.23 stays in the tree under io-http, io-imap, io-sasl and the other io-* crates.
- src/main.rs: `main` calls `SimdCpu::install_detected()` first (simd-cpu 0.1, `std`), so the base64 and quoted-printable codecs mime-rs reads mail with run the detected backend instead of the portable one.
- `idna_adapter = "=1.0.0"` drops the ICU4X crates: an `http` or `https` URL with a non-ASCII host (a JMAP `server`, an HTTP proxy `url`, parsed by pimalaya-stream) is refused when parsed, its Punycode form working. `a_non_ascii_host_is_refused` (src/jmap/client.rs) was seen failing on the ICU4X back end. IMAP, SMTP and ManageSieve servers are parsed by `parse_server` as `imap`, `imaps`, `smtp`, `smtps`, `sieve`, `sieves` or `unix` URLs, which url keeps opaque: `imaps://bücher.example` reads its host as `b%C3%BCcher.example` before and after, never resolving, so nothing there needed Unicode IDNA. A SOCKS proxy URL is opaque the same way. The Gmail and Graph hosts are fixed ASCII names, and Himalaya runs no OAuth flow of its own.
- The IMAP envelope subject and display names (src/imap/backend.rs `envelope_from` and `address_from`, src/imap/utils.rs `to_address`, `imap fetch`, `imap thread`) are read through `header::decode_bytes` (src/shared/message/header.rs), the reading `message read` applies to a header, rather than rfc2047-decoder, which brought base64 0.22, charset, quoted_printable and chumsky's default `stacker` (stacker, psm). Over the decoder cases tried, the two agreed but on four: a character split across two encoded words is rebuilt, raw 8-bit bytes read as Windows-1252 rather than Latin-1, an encoded word beside such bytes is decoded rather than the whole string left raw, and a UTF-7 encoded word stays as written, as `message read` has shown it since mime-rs. `an_envelope_reads_its_header_strings_as_message_read_does` was seen failing on the previous decoder.
- deny.toml lists Ortie's targets under `[graph] targets`, which clears the windows-sys duplicate; the allowed licences are the ones the tree carries: Apache-2.0, BSD-3-Clause, ISC, MIT, MPL-2.0, Unicode-3.0 and Zlib, which foldhash needs under chumsky's and rusqlite's hashbrown. 0BSD, `Apache-2.0 WITH LLVM-exception` and CDLA-Permissive-2.0 leave.
- `JmapConfig::server`'s doc names the `http` and `https` schemes `parse_server_url` takes, not `jmap` and `jmaps`, and the ASCII host.
- The `[patch.crates-io]` pins are unchanged.

Capabilities moved: packaging (cairn/spec/packaging.md: "Hosts are ASCII", "Dependencies name their features" and "Dependency checks pass clean" added), backends (cairn/spec/backends.md: "An IMAP envelope reads its strings as a header" added).

Verified: `cargo fmt`; `cargo clippy --all-targets -D warnings` with the default features, `--all-features` and `--no-default-features --features rustls-ring,imap,smtp`; `cargo test --all-features` (495 tests); `cargo deny check` (advisories, bans, licences and sources ok); `json-schema -d` writing the same 215 schemas from the default release build and 223 from an all-features build. `--no-default-features` with `rustls-ring` alone, `native-tls,jmap` and `rustls-ring,maildir,mbox,m2dir,pimdir` fail clippy on dead code and unused imports (104, 10 and 15 distinct diagnostics), the same diagnostics as on ddcbaa4. Release binary (default features, `cargo build --release --locked`, one build each): 18,083,408 bytes before, 17,900,624 after (-182,784, -1.0%). Normal tree (`cargo tree -e normal --prefix none`, unique crates, himalaya included): 218 before, 185 after with every feature; 206 before, 173 after with the default ones. Cargo.lock: 304 packages before, 270 after.
