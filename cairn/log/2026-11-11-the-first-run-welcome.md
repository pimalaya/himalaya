# The first-run welcome

Himalaya meets a person without a configuration as Ortie does (ortie 2026-11-10-welcome-without-config), on pimalaya-config's typed account resolution.

- Cargo.toml: pimalaya-config takes a path patch on ../config beside pimalaya-cli's (`[patch.crates-io]`, Cargo.lock moving from the registry 0.3.0 to the checkout's 0.3.1); pimalaya-cli gains its `mcp` feature, for `exit_on_failure`; clap drops `env`, nothing reading a variable any more.
- src/config.rs: `impl TomlConfig for Config` gains `sample_url` (the config.sample.toml page) and `accounts`; `take_named_account` keeps handing the account proxy down. Himalaya's `take_default_account` and its `take_account` override refusing several defaults go, the shared `take_account` refusing them with the same wording (`AccountError::SeveralDefaults`), listing the held accounts for an unknown one (`AccountError::Missing`) and naming both ways of picking one when none is marked (`AccountError::NoDefault`). `NO_CONFIG_HINT` goes; a missing configuration now reads `No configuration found at <path>, start from the sample: <URL>` (`ConfigMissingError`).
- src/cli.rs: `resolve_account` is `Config::load` then the shared `take_account`, still returning the leftover `Config`. `meet_bare_invocation` (the help when a configuration exists, a broken one included, `ConfigMissingError` otherwise), `welcome()` building pimalaya-cli's `Welcome` (bin `himalaya`, first command `envelope list`) and `SAMPLE_RAW_URL` (the raw config.sample.toml `curl` fetches) mirror Ortie's. The `mcp` branch hands every failure of the server to `exit_on_failure::<ErrorCode, _>`, which prints it as text on stderr and exits 1, but returns a `ConfigMissingError` when `is_wanted`, for `main` to print the welcome. `ConfigPathsArg` and `CONFIG_PATH_DELIMITER` give way to pimalaya-cli's `ConfigFlags`.
- src/main.rs: `main` builds the `SessionAccount` from the parsed flags, runs `execute`, then downcasts `ConfigMissingError`: with `--json` off and stderr a terminal it prints the welcome on stderr, with `shipped_sample("himalaya")`, and exits 1; any other result goes to `ErrorReport::eval_coded` as before. The header describes the welcome and the stderr it uses.
- src/account: `account check` and `account capability` resolve through `resolve_account` rather than their own loading, which named no path; `account list` loads through `Config::load` without taking an account, and its rows name `pimdir`, which `AccountRow::from_account` skipped, between `mbox` and `smtp`. The `account` help no longer says bare `himalaya` creates an account.
- src/repl.rs and src/mcp.rs are untouched: both still resolve the account up front through `resolve_account`, so a missing configuration reaches `main` (the REPL) or the `mcp` branch typed.
- The integration tests drop their `env_remove("HIMALAYA_CONFIG")`, the variable being read no more.
- README (Configuration: the welcome, `-c` once per path, `-c "$HIMALAYA_CONFIG"`), config.sample.toml header (the paths merge rather than the first valid one being read, one path per `-c`), CHANGELOG (the welcome added, the MCP failures on stderr, `-c` changed and `HIMALAYA_CONFIG` removed as **BREAKING**, the Windows `-c` fix folded into the former, `account list` naming `pimdir` fixed, the REPL entry refusing `mcp` rather than the gone `configure`).

Tests: `a_delimited_config_value_stays_one_path` replaces the two asserting the platform delimiter (a value holding `:` and `;` is one path, repeated flags keep their order); `a_missing_configuration_is_typed_for_the_welcome`, `an_unknown_account_lists_the_held_ones` and `several_default_accounts_are_refused_naming_them` in src/cli.rs; `a_pimdir_block_is_listed_among_the_backends` and `a_missing_configuration_names_the_path` in src/account/list.rs; tests/first_run.rs runs the binary with stderr piped: bare with a configuration and with a broken one prints the help, bare without one names the missing path and prints no welcome, `--json account list` without one prints the failure object, `mcp` without one leaves stdout empty and says why on stderr. The `pimdir` row and the `mcp` stdout tests were seen failing against the old code.

Verified: `cargo fmt`; clippy clean with `-D warnings` for the default features, `--all-features` and `--no-default-features --features rustls-ring,imap,smtp`; `cargo test --all-features` passes (421 unit tests and the integration suites). Under `script` with an empty home: bare `himalaya`, `-c <missing> envelope list`, `repl`, `account list` and `mcp` (stdout captured, 0 bytes) print the welcome with the `curl` command, no sample shipping under target/, and exit 1; `--json` prints the failure object and a piped stderr the text error. `HIMALAYA_CONFIG` pointing at a valid file is ignored. The `json-schema` output is byte-identical to the previous binary's, 223 schemas with all features.

Spec: config (Config loading and merge, Missing account is an error modified; A missing configuration meets a person with the welcome, A bare invocation shows the help added), commands (Output discipline modified; An account list names every block added), mcp (An MCP server over stdio modified).

Left: shipping config.sample.toml as share/doc/himalaya/config.sample.toml in the release archives, install.sh and the Nix output, so the welcome copies it rather than downloading; the REPL and MCP moves onto pimalaya-cli's shared core; released pimalaya-cli and pimalaya-config replacing the path patches.
