# The pimdir backend follows storage-draft-08 and search-draft-08

Built against io-pimdir bff5737 (pimdir d671bbd: storage-draft-08, sync-draft-07, search-draft-08) through the `path = "../io-pimdir"` patch. The end-to-end run on a scratch store neverest synced and the git pin of bff5737 are still open in tasks.md.

- Build: the dev-only `rusqlite` moves to 0.41, the one io-pimdir links; Cargo.lock moves rusqlite and libsqlite3-sys alone. The compile port: `PimdirBlobs::open(dir)` and `PimdirBlobs::path` answering `io::Result`, `io_pimdir::hash::hash` for the attachments test, the tag types read from `io_pimdir::search::tag`. The second pass found nothing more: no exhaustive match on `PimdirError` or `PimdirQueryErrorCode`, and Himalaya reads neither `address_placements`, `count_mail_by_day` nor the drain and collector reports. `cargo check --all-targets` is clean on the default features and on `--no-default-features --features rustls-ring,pimdir`.
- Submit: `PimdirSubmit` carries no `object`, the message being the row's body, and its `source` is required. The performer is the declared one as before, else the one source syncing the anchor, which the payload now names where it named none (STORAGE Annex B.2: a producer files the copy itself beside a `submit` to an undeclared performer, as Himalaya already did). A mailbox no source syncs yet is refused with `no-performer`, several undeclared sources with `ambiguous-performer`. Test `a_send_no_source_performs_stages_nothing`; the send tests make a source sync `imap/Sent` and check the payload without `object` and with `source`. This one came with the compile port, so it never ran against the old behaviour, which no longer builds.
- Error vocabulary (src/error.rs, the `himalaya-error` schema following it): `store-newer` and `store-stale` are gone; `store-version`, `sync-version`, `store-exposed`, `flag-invalid`, `action-malformed`, `conflict-unread`, `index-version` and `index-zone-unknown` are relayed; `store-hash-algo` stays, io-pimdir still raising it. `pimdir_error` adds to a `store-version` refusal that Himalaya is upgraded when the store's sync engine is newer, else the store reinstalled as neverest's MIGRATION.md says; nothing says to delete it. A submit payload `PimdirSubmit::to_action` refuses is `action-malformed`, as the enqueue would code it (no test: `SubmissionEnvelope::parse` refuses first what the payload rules refuse).
- Flags: `parse_flag` refuses a flag the store cannot hold (empty, whitespace, a control or a non-ASCII character) with `flag-invalid`, so `pimdir flag` and `pimdir tag` answer what io-pimdir's enqueue answers; the IMAP-only refusals keep no code.
- Tests failing first: `a_store_of_another_draft_is_refused_saying_to_reinstall_it` (format_version rewritten to storage-draft-07 and storage-draft-09 through rusqlite), `a_cancel_leaves_a_store_of_another_draft_alone`, `a_store_others_can_read_is_refused_as_exposed`, `a_flag_the_store_cannot_hold_is_refused_and_stages_nothing` (backend, past the flag check), `a_flag_the_store_cannot_hold_is_coded_flag_invalid` (`parse_flag`) and `an_index_of_another_draft_is_refused_as_index_version` were written with the compile port done and the new variants in `ErrorCode` but not yet relayed: all six failed with `left: None` where the code was expected. They pass once relayed. `a_newer_store_is_refused_saying_to_upgrade` and `a_stale_store_is_refused_saying_to_run_the_sync_engine` gave way to these and to `a_damaged_store_is_refused_as_corrupt` (a dropped table is `store-corrupt` now); `a_database_another_program_wrote_is_refused_as_foreign` restricts the directory and the database it creates, tempfile making the directory `0755` and SQLite the file `0644`, which io-pimdir refuses as exposed before reading it.
- Search: `a_query_past_its_bounds_is_refused_as_limit_exceeded` covers the 1,024-character, 32-group and 128-term bounds in both renderings. The ariadne and JSON renderings print any §8.4 code, so this needed no change and passed at once: a coverage test of the new upstream code, not a regression test.

Capabilities moved: **backends** (A pimdir store failure carries its code, the queue cancel paragraph and scenario, pimdir writes name their queue row, pimdir stages flags by their raw spelling, pimdir sends by queueing a submit intent: modified), **commands** (the JSON error code table: modified), **search** (pimdir searches through the store's index, A missing or outdated pimdir index is a coded error, A refused pimdir query names its fault: modified).
