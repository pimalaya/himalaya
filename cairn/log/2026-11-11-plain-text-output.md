# Plain text output

The owner's direction: "pure text data, no table, no colour". Every text output now prints through pimalaya-cli's `columns::Columns` (lists) or `fields::Fields` (records), both from the checkout the path patch points at.

- Lists: an uppercase header, one item per line, columns two spaces apart, an empty cell `-`, no border, colour, truncation or leading blank line. The free-text column moves last and the others keep their order: `envelope list|search` (ID, FLAGS, [ATT], FROM|TO, DATE, SIZE, SUBJECT), `mailbox list` (ID, ROLE, [TOTAL, UNREAD], NAME), `attachment list|download` (ID, TYPE, SIZE, [INLINE], FILENAME, [PATH]), `imap list` (DELIMITER, ROLE, ATTRIBUTES, NAME), `jmap email query|get` (ID, FLAGS, FROM, DATE, SUBJECT), `jmap mailbox query|get` (NAME last), `jmap identity get` (ID, EMAIL, NAME), the Gmail labels, threads and send-as lists, the Graph messages, folders and attachments lists, `sieve list` (ACTIVE, NAME), `pimdir mailbox list`, `pimdir attachment list|search` (FROM then NAME last), `pimdir queue list` (SUBJECT last), `pimdir search` (MATCHED before FROM, SUBJECT, SNIPPET), `pimdir search --threads` (HITS before FROM, SUBJECT), `pimdir tag` (SUBJECT last). Multi-valued cells join with `,` (account backends, IMAP attributes, pimdir mailboxes, hits and flags). A FLAGS cell holds only the glyphs that apply, `-` for none. `jmap thread get` lists one (THREAD ID, EMAIL ID) row per email; `gmail history list` prints `New history id` as a field, then its records as ID, ADDED, DELETED, LABELED, UNLABELED. `imap search` and `imap sort` lose their `Found N message(s)` trailer. Account names, mailbox names, ids and the other server strings these lists print now all go through `sanitize::text`, which some did not.
- Records: `account check` (`Account:` then one `<backend>:  OK|FAIL (...)` per backend), `imap select`, `imap status`, `imap id` (sorted by parameter), `imap fetch` (one record per message, a blank line apart, the structure tree under its label), `vacation get|set`, `jmap vacation get`, `sieve capability`, the Gmail gets (draft, message, profile, thread, settings: auto-forwarding, delegate, filter, forwarding address, IMAP, language, POP, send-as, vacation) and the Graph message and profile gets, the header block of `message read` and `message parse`. Multi-line bodies (vacation texts, signatures) go through `sanitize_body`. `MessageTemplateOutput` is untouched.
- Newlines: `maildir|m2dir|mbox message save`, the Gmail draft writes and `jmap query` end with one; `sieve get` adds one only when the script lacks it; `jmap email parse` puts a blank line between bodies, each closed by a line break.
- Config: the `*-color` keys of `envelope.list.table`, `mailbox.list.table`, `attachment.list.table` and `account.list.table`, `table.preset` and `table.arrangement` are gone, with `MailboxListConfig`, `AttachmentConfig`, `AccountListingConfig`, `TableConfig`, `TableArrangementConfig` and their account getters and merges; the glyph keys stay. A test pins the refusal of a colour key (fails against the old schema).
- `-w/--max-width` leaves `envelope list`, `envelope search`, `mailbox list`, `pimdir search`, `pimdir thread`, `pimdir tag`, `pimdir mailbox list` and `pimdir attachment list|search`, and the MCP filter hiding it from the tools goes.
- Cargo.toml: crossterm out; clap takes `default-features = false` with derive, env, error-context, help, std, suggestions and usage, so help prints without colour and unwrapped; `env` stays while `-c` reads `HIMALAYA_CONFIG`.
- ariadne renders with `with_color(false)` in src/shared/envelope/search.rs and src/pimdir/index.rs, where a terminal used to get ANSI escapes, inside the `--json` error string too.
- src/shared/table.rs (the comfy-table preset mapper) is gone; `table::sanitize` is `sanitize::text`, now called from 69 files (40 print a `Columns`, 25 a `Fields`). `PimdirTableStyle` became `PimdirListStyle`. The one em dash of the plain output (`message read` part lines) became a comma.

Verified: the suite passes with all features, tests asserting the old output moved to the new one (message read headers, account check, pimdir flag list) and a new one pinning an envelope list byte for byte; clippy is clean on the three feature sets; a scratch Maildir listed and read as above; a `-w` is refused. The `json-schema` output is structurally identical; 33 schemas differ in descriptions only, the output types' doc comments no longer saying "table".

Spec: commands (Text output is plain text, Help is plain text, A query error is drawn without colour added), config (No colour is configured added), backends (The envelope carries its threading pointers, Mailbox role reworded) and the provider test plan (no width row).
