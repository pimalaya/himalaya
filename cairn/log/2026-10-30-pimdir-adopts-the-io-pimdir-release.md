# The pimdir backend adopts the io-pimdir release API

From the pimdir stable-release plan (Apps Phase A). io-pimdir's release API (the-producer-stages-its-own-body and errors-carry-a-stable-code, both 2026-10-30) is taken from the local checkout through a temporary `path` entry in `[patch.crates-io]`, until those changes are pushed; the lockfile diff is the io-pimdir `source` line alone. Returning it to a git rev, the 0.9 requirement and deny.toml moved to v2-release.

- Store errors: src/error.rs maps `PimdirError::code()` to Himalaya's `ErrorCode` (`store-newer`, `store-older`, `store-uncreated`, `store-corrupt`, `store-not-current`, `store-stale`, `store-hash-algo`, `store-busy`, `store-owned`, `store-staging`, `store-in-flight`, `item-duplicate`, `unsupported`, `no-performer`, `ambiguous-performer`; SQL, I/O, JSON and malformed actions carry none), and `pimdir_error` wraps a failure as a `CodedError` keeping io-pimdir's message, each call site adding its own context instead of formatting the error into its message. The `queue cancel` refusals and the ambiguous performer keep their wording and gain `store-owned` and `ambiguous-performer`; a store of another schema now takes io-pimdir's advice, which tells a newer store (upgrade this program) from an older or reshaped one (run the sync engine). Nothing advises deleting the store. Tests `a_newer_store_is_refused_saying_to_upgrade`, `a_stale_store_is_refused_saying_to_run_the_sync_engine`, `a_cancel_during_a_sync_is_refused_as_owned`, and the vocabulary test `a_relayed_pimdir_code_keeps_io_pimdirs_spelling`.
- Duplicate creates: `add_message` checks the gate for its partial supports, then appends through `PimdirProducer::enqueue_add`, which refuses a link id live or pending in the mailbox as `item-duplicate`, queueing nothing. Tests `an_add_already_queued_is_refused_and_stages_nothing` and `an_add_the_mailbox_holds_is_refused_and_stages_nothing`, which failed on the old `enqueue` path with "called `Result::unwrap_err()` on an `Ok` value: PimdirStaged { queue_id: 2, message_id: \"d1@x.org\" }" (and `queue_id: 1` for the held one). `a_parked_row_is_listed_and_cancelled` now parks its row by having the source list the same message after the add is staged.
- Bodies: `add_message` and `send_message` stage through `PimdirProducer::stage_body`; the `write_blob` helper is gone. The collector tests of a-staged-body-is-written-under-the-lock pass unchanged.
- Submit: the intent is `intent::PimdirSubmit { source, object, from, rcpts, subject, copy }.to_action()`; `SubmitPayload` and the local `SUBMIT` are gone. The payload carries the same keys and values as before (`v`, `object`, `from`, `rcpts`, `subject`, and `source` and `copy` when set); only the key order moved, io-pimdir writing them sorted. The send tests check the payload value and read it back with `PimdirSubmit::from_payload`, as a performer does.
- `account check` had no pimdir arm (found reading src/account/check.rs): an account declaring only a pimdir block failed with "Account `test` configures no supported backend". It now opens the store as a reader, lists the mailboxes, and opens then drops a producer. Test `a_pimdir_account_is_checked`, which failed on the old code with that error.
- Also: `Flag::iana` was gated without `jmap` and `gmail`, which use it, so the single-backend jmap and gmail builds no longer compiled; both are in the gate.

Capabilities moved: **backends** (A pimdir store failure carries its code, added; the added-message paragraph, the staging lock, the parked-row scenario and the submit payload, modified), **commands** (account check covers every declared backend, added; the JSON error code table, modified).
