# The shared REPL and MCP

Himalaya's REPL and MCP server run on pimalaya-cli's shared core (the ../cli checkout the path patch points at), as Ortie's do; Himalaya's copies of the loop, the stdin guard and the protocol answers are gone.

- Cargo.toml: pimalaya-cli gains its `repl` feature; Himalaya's own shlex dependency goes (Cargo.lock moves it under pimalaya-cli).
- src/repl.rs (147 lines to 54): `ReplCommand::execute` resolves the account up front as before, then runs `Repl::new("himalaya", json)` with `-b` and `--backend` added to the fixed flags; the closure refuses `repl` and `mcp` (`Cannot start a session inside a session`) and runs any other command over the kept `Session`. `ReplLine`, the hand-rolled loop and the `println!()` after text results go; it takes `&impl Printer`, the loop building a printer per line. `IN_SESSION`, `claim_stdin`, `check_stdin` and `in_session` go: src/shared/raw.rs, src/shared/message/parse.rs, src/shared/message/arg.rs, src/jmap/query.rs and src/sieve/script.rs call `pimalaya_cli::session::check_stdin(ErrorCode::StdinTaken)`, src/shared/message/builder.rs `in_session`.
- src/mcp.rs (1575 lines to 1344, tests included): `McpCommand::execute(session)` lists the tools, then `mcp::serve(&INFO, &definitions, |call| server.call(call))`, which claims stdin; src/cli.rs passes no printer to it and keeps its `exit_on_failure` branch. `INFO` carries `instructions` (finding a mailbox and an envelope id, the query language, attachments as embedded resources and `attach-data`, the two gates, the `himalaya-error` object). `McpToolSpec::all` builds each tool's input from `Grammar::new(&[group, leaf], cmd).retain(..).fixed(..).one(..)`, the gates and `without` in `retain`, the server-only arguments inserted into `input_schema()`, `readOnlyHint` and `openWorldHint` read off `names()`, the output schema through `tool_output_schema` (the part schema for `attachment_download`). `call` parses `grammar.argv` back through `McpLine`, hands the server-only arguments, runs the command into a `CapturePrinter`, and `tool_result` builds `ToolResult::printed::<ErrorCode>`, moving a part's `data` into the embedded resource on that result. `McpServer::answer`, `failure`, `PROTOCOL_VERSION`, `McpPrinter`, `McpToolArg`, `argv`, `exposes`, `scalar` and `McpTool::fixes` go.
- Behaviour now shared: a `#` comment line is skipped (it answered a parse error); `--json` on a line switches that line alone (it was refused); a line setting `-a`, `-c`, `--log-level`, `-b` or `--backend` answers ``Cannot set `<flag>` inside a session, start a new session with it instead`` (clap's error before); the help goes to stderr in a JSON session (stdout before) and reads `Usage: himalaya [OPTIONS] <COMMAND>`, its about no longer leaking `ReplLine`'s doc comment; no blank line follows a text result. The server requires `"jsonrpc": "2.0"`, answers a batch or a non-object -32600 with a null id (nothing before), a non-UTF-8 line -32700 and reads on (the server ended), echoes a supported `protocolVersion`. A command printing no value or several answers the typed `himalaya-error` object, its count right (untyped text, off by one for several), and so does a part tool printing no part. An unknown argument reads ``Unknown argument `<key>`, <tool> takes `<a>`, ...`` (``expected one of: ...``), refused by pimalaya-cli before the call reaches Himalaya; two `attachment-id` values are refused by the grammar, ``Argument `attachment-id` takes exactly one value``, before the command runs.
- README (the REPL paragraph: `#` comments, per-line `--json`, refused session flags, help on stderr), CHANGELOG (the unreleased `himalaya repl` and `himalaya mcp` entries amended, the stale "`attachment download` ... not exposed" dropped), src/main.rs header (the shared core, stderr carrying the prompt and the JSON-session help), src/session.rs doc.

Tests, each seen failing against the old code first: tests/repl.rs `a_line_json_flag_switches_that_line_alone`, `a_session_flag_is_refused_by_name`, `a_comment_line_is_skipped`, `help_goes_to_stderr_in_a_json_session`; tests/mcp.rs `initialize_tells_the_agent_how_to_use_the_tools`, `a_message_that_is_no_request_is_refused_and_the_server_goes_on` (a batch, a non-UTF-8 line, a request without `jsonrpc`, then a ping); src/mcp.rs `a_wrong_count_of_values_is_the_typed_failure_object` (zero and two values, a part tool printing no part), run against the old result-building logic extracted into the same `tool_result` signature. Added: `the_instructions_name_existing_tools`. Ported: the MCP unit tests onto `tool.grammar`, `an_unknown_key_names_the_server_only_arguments_too` onto `pimalaya_cli::mcp::read`, `the_download_tool_takes_exactly_one_part_id` onto the grammar's refusal of two ids (the command's refusal of none stays).

Verified: `cargo fmt`; clippy clean with `-D warnings` for the default features, `--all-features` and `--no-default-features --features rustls-ring,imap,smtp`; `cargo test --all-features` passes (423 unit tests, 1 ignored, and the integration suites). `json-schema -d` is byte-identical before and after (223 schemas); `tools/list` without flags and with `--allow-write --allow-send` is identical to the old binary's (jq-sorted). A session driven over stdio by a Python script (jsonschema 2020-12) on a scratch Maildir: every input schema an object, every output schema an object root, `envelope_list`, `mailbox_list`, `envelope_search`, `attachment_list` and `attachment_download` returning `structuredContent` valid against their `outputSchema`, an unknown and a gated tool -32602, stdout holding JSON-RPC responses only and stderr empty.

Spec: repl (A session runs the CLI over one account, A piped session answers once per line modified; A line switches itself to JSON, Session flags are refused by name, Help keeps JSON lines whole added), mcp (An MCP server over stdio, A tool's input is the command's grammar, A tool's output is the command's payload modified; The server tells the agent how to use it added), commands (Output discipline modified).
