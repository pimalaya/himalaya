# The sample is tested and shipped

config.sample.toml takes Ortie's shape (ortie 2026-11-10-providers-in-the-sample), from 515 lines of prose-commented paragraphs to 198 lines of code.

- The file opens on `[accounts.example]`, no header comment, and lists the options every account shares with dotted keys: `default`, `email`, `display-name`, `signature`, `signature-delim`, `downloads-dir`, `message.send.save-copy`, the two posting styles, `envelope.list.*`, seven `mailbox.alias.*` entries (inbox, the five roles, one free name) and the proxy, the default value active (`signature-delim = "-- \n"`, `message.send.save-copy = false`, `envelope.list.page-size = 25`, the four glyphs...) and the others commented, every line ending in one comment aligned per block at column 40 or the next tab stop past the block's longest line. The proxy with credentials is one inline table, `proxy.username` and `proxy.password` failing alone without `proxy.url`.
- Eleven sections follow, each a paragraph headed `# <Name>` then `#`, holding a working account once uncommented, its own alternatives commented twice: IMAP and SMTP (PLAIN, the server forms, `unix://`, STARTTLS, `authzid`, `sasl-ir`, `id.auto`, `id.fields`, `sort.fallback`, ALPN, TLS, per-backend proxy, `message.send.save-copy = "Sent"`), ManageSieve, JMAP (the session URL active, a bare authority's `/.well-known/jmap` failing on a redirect; HTTP Basic, the identity and the drafts and sent mailboxes), Gmail, Microsoft Graph, Microsoft IMAP and SMTP (`outlook.office365.com`, `smtp://smtp.office365.com:587` with STARTTLS, XOAUTH2, as io-imap and io-smtp tests/outlook.rs verified), Fastmail (the JMAP session, a bearer token), Maildir, m2dir, mbox, pimdir. OAuth 2.0 tokens come from `["ortie", "token", "show", "-a", "example"]`, Ortie's sample holding the matching sections; password commands are `exit 127`.
- Fixed on the way: the pimdir root is neverest's shared store, ~/.local/state/neverest, not ~/.local/state/neverest/example; `downloads-dir` falls back to the system's download directory before the temporary one, not to `$TMPDIR`; the file as copied no longer holds an active IMAP and SMTP account pointed at `example.com` with the password `***`.
- Not as code lines: the SASL mechanism and the JMAP authentication are enums keyed by name, and `pimalaya_config::sample::variants` swaps a line only for the active line of the same key, so a `##imap.sasl.login.username` beside an active `imap.sasl.plain` block fails as a two-key enum. PLAIN (IMAP and SMTP, ManageSieve), XOAUTH2 (Microsoft), Basic (JMAP) and Bearer (Fastmail) stand as code; `login`, `scram-sha-256`, `oauthbearer`, `anonymous` and `jmap.auth.header` are named in the comments of those lines and in one README sentence. The `.raw` form of the token secrets stands on the Gmail and Graph tokens and every password. Prose the sections dropped lives in the spec already: the Maildir keyword round trip and the mbox cache (backends), the pimdir collection id and send anchor (backends), Coremail and the `ID` quirks (provider-quirks), the ManageSieve scheme (config).
- src/config.rs: `the_sample_configuration_parses_with_each_variant` requires the single `[accounts.example]` header, then parses each of the 348 variants `variants(&sample, &SECTIONS)` returns through `Config::load`, the loader `-c` uses, resolves `example` as the default account and requires a backend block. Cargo.toml: pimalaya-config with `sample` as a dev-dependency (the path patch on ../config carrying it). Seen failing on a scratch copy of the text with `##imap.sort.fallbak = true` (the variant named) and with `#pimdir.rot =` (the pimdir base, ``unknown field `rot` ``).
- default.nix installs config.sample.toml as share/doc/himalaya/config.sample.toml; .github/workflows/releases.yml already calls pimalaya/nix's releases.yml, whose `build-with-share` job puts the build's share/ in every archive. install.sh copies it to `$PREFIX/share/doc/himalaya/` when the archive holds it.
- README Configuration: the sample, its sections, Ortie, the shipped path and the welcome first, then the SASL and JMAP authentication shapes, the top-level fallback options, then the paths; the Outlook subsection says `xoauth2`, Exchange refusing `oauthbearer`. CHANGELOG: the shipped sample added, the sample changed.

Verified: `cargo fmt`; clippy clean with `-D warnings` for the default features, `--all-features` and `--no-default-features --features rustls-ring,imap,smtp`; `cargo test --all-features --no-fail-fast` passes (424 unit tests, 1 ignored, and the integration suites) but for tests/repl.rs `help_goes_to_stderr_in_a_json_session`, which fails on ../cli's new usage line, outside this change. `nix build .#default` fails in the sandbox before compiling, Cargo finding no ../cli and ../config for the path patches HEAD carries already; a scratch copy with both vendored and the patches pointed there built, its result/share/doc/himalaya/config.sample.toml identical to the repository's (mode 444). Its binary, run under `script` with an empty home, printed the welcome's `mkdir -p` and `install -m 644` from the store; the copy loaded with `account list` (no backend), and with the Maildir section uncommented `account check` answered `maildir: OK`.
